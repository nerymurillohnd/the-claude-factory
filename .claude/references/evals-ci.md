# Evals CI workflow

How to create `.github/workflows/evals.yml` from `.claude/templates/evals-ci-template.md`.

## Produces

`.github/workflows/evals.yml`: a GitHub Actions workflow that runs `claude plugin eval` with the full suite, only for plugins that have an eval directory and are new or had a component or dependency changed, and skips every other plugin.

## When

- When the first plugin with evals is published and the repository has no eval workflow. With an existing workflow, audit that one with the checklist below instead.
- Adding it spends CI money on every pull request that edits a plugin with evals: Nery approves it before the commit and before the push.

## Sources

Read 2026-11-10:

- Claude Code docs `plugin-evals` → Requirements ("Git 2.31 or later, if git is installed"; with an older git, `claude plugin eval` "stops before running any case") and → Run evals in CI (pinned models, `--json`, `--threshold`, `--no-publish`, `--max-cost-usd`; a CI runner needs a Claude Code install and credentials in the environment); `plugin eval` needs Claude Code v2.1.269 or later.
- Claude Code docs `authentication`: `CLAUDE_CODE_OAUTH_TOKEN` is "a long-lived OAuth token generated by `claude setup-token`", for "CI pipelines and scripts where browser login isn't available"; in the credential order `ANTHROPIC_API_KEY` comes before it, and "in non-interactive mode (`-p`), the key is always used when present".
- Claude Code docs `setup`: the native installer takes the version as `bash -s <version>`.
- GitHub Docs `/en/actions/reference/security/secure-use` (as `eval-policy.md` cites it; not reread on 2026-11-10): pin third-party actions to a full-length commit SHA; secrets are not passed to workflows triggered by `pull_request` from a fork.
- `.claude/skills/testing-plugins/references/eval-policy.md` (read 2026-10-26 against v2.1.310) for the target rule, the audit checklist and the error map.

## Placeholders

| Value | Meaning | True value from |
| :-- | :-- | :-- |
| `{{selectorScript}}` | Script that prints the plugins with evals changed between two commits | This repository: `.claude/skills/testing-plugins/scripts/changed-eval-plugins.sh` |
| `{{maxCostUsd}}` | Ceiling per plugin per run, in USD | Nery's approval |
| `{{claudeCodeVersion}}` | Exact Claude Code version, 2.1.269 or later | The release notes |

`${{ … }}` in the YAML is GitHub Actions expression syntax, not a placeholder; leave it.

## Procedure

1. Copy the template's `yaml` block to `.github/workflows/evals.yml`.
2. Fill the three values and the three `TODO` lines:
   - **Models:** create the repository variables `EVAL_MODEL` and `EVAL_JUDGE_MODEL` with exact model ids, so a model rollout is not mistaken for a regression.
   - **Cost:** `MAX_COST_USD`, approved by Nery.
   - **Claude Code:** an exact version.
3. Add the repository secret `CLAUDE_CODE_OAUTH_TOKEN`, created with `claude setup-token`. Keep `ANTHROPIC_API_KEY` out of the job, or it replaces the token.
4. Check each pinned action SHA against its latest release.
5. Keep `--threshold`, `--trust-plugin`, `--scaffold`, `--report` and `--no-publish` unless a suite needs otherwise; add `--allow-tools` with the tools the suites need.
6. Make sure `eval-results/` and `**/evals/results/` are git-ignored and `mocks/.replay/` is not.
7. Run the checks and the audit checklist.

## Audit checklist

Report each line as pass, fail or unknown, with the evidence:

1. Triggers on pull requests that touch the plugin directories and offers `workflow_dispatch` with a plugin input.
2. Targets = has evals AND (new OR a component or dependency changed); checkout has full history (`fetch-depth: 0`).
3. Nothing runs for plugins without evals.
4. The command is complete: target first, `--trust-plugin`, `--json <file>`, `--threshold`, pinned `--model` and `--judge-model`, `--no-publish`, `--max-cost-usd`, `--scaffold` when a case has a `scaffold_script`.
5. Claude Code is pinned, 2.1.269 or later; the runner's git is 2.31 or later.
6. Credentials come from a secret, and the job fails loudly when it is empty.
7. Fork pull requests get a visible warning, never `pull_request_target` with the fork's code.
8. The JSON result and the report are uploaded as an artifact.
9. Exit codes are read: 0 pass; 1 below threshold or a failure; 2 partial (cost ceiling hit or credential rejected).

## Rules

Official:

- Pin models, the Claude Code version and action SHAs.
- Fork pull requests get no secrets.

This repository:

- The full suite runs only in CI; locally only the pilot and the smoke suite run, each announced with its cost first.
- After a plugin is published, CI evaluates only plugins that contain evals and changed in the change set.

## Checks

- `actionlint .github/workflows/evals.yml`.
- The audit checklist above, every line pass.

## Never

- Never commit or push the workflow without Nery's approval of its cost.
- Never use `pull_request_target` to reach secrets for fork code.
