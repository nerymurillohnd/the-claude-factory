# Troubleshooting: public GitHub marketplaces

Source: https://code.claude.com/docs/en/plugins/troubleshooting, read 2026-10-25, plus live checks on `claude` v2.1.310 (marked **[live]**). Entries are grouped by the stage that emits the message. Success signals are what Claude Code prints once the fix works.

Contents: Triage · Commands that do not exist · Add a marketplace · Install a plugin · Installed but not working · Plugin authors · Marketplace owners · Out of scope

## Triage

| Question                             | How to answer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| :----------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Is the repo public and reachable?    | `git ls-remote https://github.com/<owner>/<repo>.git`. A private or misspelled repo ends in an authentication message, not "not found".                                                                                                                                                                                                                                                                                                                                                                  |
| Is it the repo or the local machine? | With `T` a `mktemp -d` folder: `env -u CLAUDE_CODE_PLUGIN_DIRS CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1 CLAUDE_CONFIG_DIR="$T/config" CLAUDE_CODE_PLUGIN_CACHE_DIR="$T/plugins" claude plugin marketplace add <owner/repo>`, then `... claude plugin install <plugin>@<marketplace>` with the same prefix. OK there, failing at home = local state. Failing in both = repo or entry. **[live]** on v2.1.310 this isolates settings and the plugin cache, and drops plugins `CLAUDE_CODE_PLUGIN_DIRS` would add. |
| Is the catalog valid?                | Clone the repo, run `claude plugin validate --strict <dir>` at its root (marketplace) and at each plugin root.                                                                                                                                                                                                                                                                                                                                                                                           |
| What is registered locally?          | `claude plugin marketplace list`, `claude plugin list`, `/plugin` → **Errors** tab, `claude plugin list --json` (`errors`, `errorDetails`).                                                                                                                                                                                                                                                                                                                                                              |
| Need the real error text?            | `claude --debug`, log at `~/.claude/debug/<session-id>.txt`.                                                                                                                                                                                                                                                                                                                                                                                                                                             |

`/plugin` is typed inside a running Claude Code terminal session. `claude plugin ...` is the shell form.

## Commands that do not exist

| Typed                                         | Says                                                                                                 | Use                                                                                        |
| :-------------------------------------------- | :--------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------- |
| `claude plugin add <source>`                  | `error: unknown command 'add'`                                                                       | `claude plugin marketplace add <source>` or `claude plugin install <plugin>@<marketplace>` |
| `claude plugin install <p> --project`         | `unknown option '--project'`                                                                         | `--scope project`                                                                          |
| `/install <plugin>`                           | `Unknown command: /install`                                                                          | `/plugin install <plugin>@<marketplace>`                                                   |
| `/plugin add <source>`                        | opens **Discover**                                                                                   | `/plugin marketplace add <source>`                                                         |
| `marketplace.anthropic.com` as source         | `Invalid marketplace source format...`                                                               | `anthropics/claude-plugins-official`                                                       |
| `/plugin ...` in a shell                      | `zsh: no such file or directory: /plugin`; PowerShell `The term '/plugin' is not recognized`         | start `claude`, type it there, or use `claude plugin ...`                                  |
| `/plugin isn't available in this environment` | non-interactive (`claude -p`), SDK, desktop Code tab, VS Code panel (with arguments), claude.ai/code | install from that surface's plugin UI, or from a terminal                                  |
| `claude: command not found`                   | PATH problem, not a plugin problem                                                                   | fix PATH (docs: troubleshoot-install), retry                                               |

Aliases that work: `claude plugins` = `claude plugin`, `plugin remove` = `plugin uninstall`, `/plugins` and `/marketplace` = `/plugin`.

| `Failed to clone marketplace repository:` + `SSH authentication failed` or `HTTPS authentication failed` | Typo, nonexistent or private repo, or credentials that need a prompt (Claude Code disables prompts: `Cannot prompt because user interactivity has been disabled`).                                                    | Confirm with `git ls-remote <url>` and the browser. | Refresh keeps failing offline                                                                            | Background update re-clones when the host is unreachable.                                                                                                                                                             | `export CLAUDE_CODE_PLUGIN_KEEP_MARKETPLACE_ON_FAILURE=1` (only for a checkout that already has `.claude-plugin/marketplace.json`; add once while online).                                                                                                                                                                                                                                                                                                                                                                                                              |
| Marketplace re-clones on every refresh, new git plugins show version `unknown`                           | git default ref format `reftable`. Fixed in v2.1.302.                                                                                                                                                                 | `claude update`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `Path does not exist: <path>`, `File path must point to a .json file (marketplace.json)`                 | Local-path add.                                                                                                                                                                                                       | Local paths are out of scope for this skill; mention the cause only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

## Installed but not working

Start: `/plugin` → **Installed** (enabled?), then the **Errors** tab, then `/reload-plugins` if it was installed in this session. `claude plugin list` shows version, scope and `Status: ✔ enabled`.

| Symptom / message                                                                                                                               | Cause and fix                                                                                                                                                                                                                                                                                                                                    |
| :---------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Run /reload-plugins to apply.`                                                                                                                 | Activation deferred (prompt-cache cost or failed attempt). The panel runs the reload for you. `Reloaded:` + counts = active; `N errors during load. Run /plugin for details.` = open Errors. `This reload changes MCP tools (...)... Run /reload-plugins --force to apply.` = would invalidate the prompt cache; use `--force` or a new session. |
| `Plugin "<name>" not cached at <path>` (guidance `Run /plugin to refresh the plugin cache`)                                                     | Install record exists, directory gone. `claude plugin install <name>@<marketplace>` re-downloads, then `/reload-plugins`.                                                                                                                                                                                                                        |
| `The packages it lists are not installed` / `were not installed, because ...`                                                                   | No `node_modules`. First: retry with the `claude plugin update <name>@<marketplace>` the note gives (skipped while `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is set). Second: install cannot run (Yarn/pnpm/`bun.lockb`, or package manager missing); author replaces the lockfile, or install the manager and update.                          |
| `installed_plugins.json holds a record under "<id>" that this version of Claude Code cannot read` (`failureCode: "install_records_unreadable"`) | Written by another (newer) version. In order: `claude update`; uninstall with the version that wrote it; delete that record by hand, then restart or `/reload-plugins`.                                                                                                                                                                          |
| `installed_plugins.json could not be read and was rebuilt`                                                                                      | Old file kept as `installed_plugins.unreadable.<date>.<hash>.kept`. Read it, reinstall what is missing.                                                                                                                                                                                                                                          |
| `install records under names that no version of Claude Code can use were removed...`                                                            | Informational; nothing to do.                                                                                                                                                                                                                                                                                                                    |
| `<settings file> does not load (...), so Claude Code ignores the whole file...`                                                                 | The settings file is invalid (`its "<key>" is not valid` / `it is not a JSON object`). Fix it, rerun the command if its change is missing.                                                                                                                                                                                                       |
| `Disabled in ~/.claude/settings.json but still loads`                                                                                           | A higher-precedence source enables it. Set the id to `false` in `.claude/settings.local.json`.`required by your org` = claude.ai sync: out of scope.                                                                                                                                                                                             |
| `Plugin "<name>" is enabled in project settings but isn't installed here`                                                                       | Project settings enable, not install. `claude plugin install <name>@<marketplace> --scope project`, then `/reload-plugins`.                                                                                                                                                                                                                      |
| Windows: still listed after `plugin uninstall`                                                                                                  | Two records spelled differently (`c:\work\app` vs `C:\work\app`). Run the same uninstall again, same `--scope` and folder. Before v2.1.295 the second run fails with `is not installed in project scope`: `claude update`.                                                                                                                       |
| `Failed to load hooks from <path>: <reason>`                                                                                                    | `hooks/hooks.json` invalid JSON/schema; `claude plugin validate --strict <plugin-dir>`.`hooks path not found: <path>`: manifest `hooks` path wrong.                                                                                                                                                                                              |
| `<Event> hook error: Failed with non-blocking status code: <stderr>`                                                                            | The hook ran and its command failed (e.g. `node: command not found`: install it / fix PATH). Path cut at a space = unquoted `${CLAUDE_PLUGIN_ROOT}`; quote it or use exec form. A hook exiting 2 blocks; since v2.1.281 the error ends `This hook comes from the <plugin> plugin.`                                                               |
| Hook loads, never fires                                                                                                                         | Note `Its hooks.json hooks do not run` in plugin details = same-name plugin registered first. Else: event name is case-sensitive (`PostToolUse`), matcher matches the tool name, trigger it on purpose, read the debug log.                                                                                                                      |
| `Failed to run: Plugin directory does not exist: <path> (<plugin> — run /plugin to reinstall)`                                                  | Run `/reload-plugins` first; read its output (`Reloaded:`; errors; or `... Run /reload-plugins --force to apply.`).                                                                                                                                                                                                                              |
| `Invalid MCP server config for "<server>": <error>`                                                                                             | `Missing environment variables: <names>` = set them in the shell that starts Claude Code, new session. `URL is unset or invalid` = `/plugin configure <plugin>`.`has an invalid MCP url` / `headersHelper ... references ${user_config.*}` = plugin's own config; author fixes.                                                                  |
| `Bundled MCP server "<name>" was not started: it needs configuration`                                                                           | MCPB bundle needs `user_config`: **Configure** in `/plugin` → **Installed**; shows `Configuration saved.`                                                                                                                                                                                                                                        |
| MCP server configured, never connects                                                                                                           | `/mcp` for status; `claude --debug` log. A schema-invalid `.mcp.json` entry only appears in the debug log (`Invalid MCP server config for <server> in <path>`); `claude plugin validate` reports it since v2.1.281. Works with `--plugin-dir`, fails installed: use `${CLAUDE_PLUGIN_ROOT}`.                                                     |
| LSP: `Executable not found in $PATH: "<binary>"` / `LSP server <name> failed to start`                                                          | Install the language server binary on the PATH of the shell that starts `claude`; new session. Memory heavy: `/plugin disable <plugin>`.                                                                                                                                                                                                         |

## Plugin authors (before publishing to the marketplace)

| Message                                                                                               | Cause and fix                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| :---------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `commands path not found: <path>` (same for `skills`, `agents`, `hooks`)                              | Manifest path resolves to nothing. Paths are relative to the plugin root and start with `./`. Outside the root: `<component> path escapes plugin directory`. Fix, `/reload-plugins`.                                                                                                                                                                                                                                                                                                   |
| `--plugin-dir` at a marketplace root loads nothing, no error                                          | Point it at the plugin root (contains `.claude-plugin/plugin.json`): `claude --plugin-dir ./my-marketplace/plugins/my-plugin`.                                                                                                                                                                                                                                                                                                                                                         |
| Works from source, fails installed (`../shared-utils`)                                                | The installed copy lives in the cache. Keep shared files inside the plugin dir (or a symlink inside it) and use `${CLAUDE_PLUGIN_ROOT}`.                                                                                                                                                                                                                                                                                                                                               |
| `${CLAUDE_PLUGIN_ROOT}` has forward slashes on Windows                                                | Intentional in shell form, which runs in Git Bash and takes `C:/Users/...` paths; exec form and PowerShell keep native backslashes. Check the form the hook uses and the Windows support its README declares against `/en/plugins/manifest-reference` → Quoting and path separators and `/en/hooks` → Exec form and shell form. |
| Plugin listed, skills missing                                                                         | `skills/` and `commands/` belong at the plugin root; only `plugin.json` goes in `.claude-plugin/`. Entry pointing at the `SKILL.md` file: `path is a file; skills entries must be directories containing SKILL.md`.                                                                                                                                                                                                                                                                    |
| Skill runs by `/plugin:skill` but Claude never invokes it                                             | In order: `disable-model-invocation: true` (the starter template sets it); description does not match how people ask; description truncated when many skills are installed. Measure with an eval case using a `tool_used: Skill` grader.                                                                                                                                                                                                                                               |
| `<directory> is not a plugin or skill folder` (from `claude plugin eval init`)                        | Run from the plugin root (or skill folder), or pass `--eval-dir`.                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `userConfig` dialog never appears                                                                     | Only interactive installs ask. Shell: `claude plugin install p@m --config key=value`; it prints `N userConfig options not yet set — run /plugin configure <plugin>@<marketplace> in Claude Code, or pass --config KEY=VALUE.` Undeclared key: `⚠ Installed, but --config not applied: --config key "<key>" isn't declared in this plugin's userConfig.` `claude plugin configure` and `<server>.<key>` need v2.1.285+.                                                                 |
| `Plugin <name> has conflicting manifests: both plugin.json and marketplace entry specify components.` | Entry has `strict: false` and declares components. Remove them, or `strict: true`.                                                                                                                                                                                                                                                                                                                                                                                                     |
| `Warning: No commands found in plugin <name> custom directory` (debug log only)                       | `commands` path exists but holds no `.md`/`SKILL.md`.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `claude plugin validate` errors (`Found N errors`, `Validation failed`, exit 1)                       | See table.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

`claude plugin validate --strict <path>` messages (with `--strict`, warnings fail too):

| Message                                                                                                                             | Fix                                                                                              |
| :---------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------- |
| `File not found: <path>` / `No manifest found in directory. Expected .claude-plugin/marketplace.json or .claude-plugin/plugin.json` | Run at the plugin or marketplace root (contains `.claude-plugin/`).                              |
| `Invalid JSON syntax: <parse error>`                                                                                                | Fix the JSON; until `hooks/hooks.json` is fixed, a session loads the plugin without those hooks. |
| `Path not found: <path>. The runtime loader will report this as a load failure.`                                                    | Fix the path or create the directory.                                                            |
| `Path contains ".." which could be a path traversal attempt: <path>`                                                                | Use paths inside the plugin root.                                                                |
| `Path is a file; skills entries must be directories containing SKILL.md`                                                            | Point at the parent directory (or `.` for a root-level `SKILL.md`).                              |
| `No frontmatter block found` / `YAML frontmatter failed to parse: <error>`                                                          | Fix frontmatter between `---` lines. Only fails with `--strict`.                                 |
| `Plugin name "<name>" is reserved: it passes as one of Anthropic's own`                                                             | Rename.                                                                                          |
| `Unknown field '<key>'`                                                                                                             | Remove or rename it. Ignored at load time; fails only with `--strict`.                           |

## Marketplace owners

| Symptom                                                                                                                                                              | Cause and fix                                                                                                                                                                                                                                                                                                  |
| :------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| URL marketplace (`https://example.com/marketplace.json`): `its marketplace entry path does not stay inside the marketplace directory` / `Plugin source path refused` | Only the JSON file is downloaded, so relative `./plugins/x` sources break. Use `{ "source": "github", "repo": "owner/repo" }` per entry, or have users add the git repo URL (a git source clones everything, so relative paths resolve). For a GitHub-hosted marketplace, the repo itself is the right source. |

`claude plugin validate --strict .` at the marketplace root (marketplace-level messages):

| Message                                                                                                                     | Kind    | Fix                                                                                           |
| :-------------------------------------------------------------------------------------------------------------------------- | :------ | :-------------------------------------------------------------------------------------------- |
| `Duplicate plugin name "<name>" found in marketplace`                                                                       | Error   | Unique names.                                                                                 |
| `Path contains "..": <path>` under `plugins[N].source`                                                                      | Error   | Paths relative to the marketplace root, no `..`.                                              |
| `Marketplace name cannot contain control or bidirectional-formatting characters` / same for plugin name                     | Error   | Remove the character.                                                                         |
| `Claude Code cannot install plugins from marketplace "<name>". Each part of a plugin id...` / `...plugin "<name>"...`       | Error   | Rename to letters, digits, `.`, `_`, `-`, starting with a letter or digit.                    |
| `Marketplace has no plugins defined`; `No marketplace description provided`                                                 | Warning | Add entries / a top-level `description`.                                                      |
| `Plugin name "<name>" is not kebab-case`                                                                                    | Warning | Lowercase letters, digits, hyphens (claude.ai sync needs it).                                 |
| `Entry declares version "<a>" but <path>/plugin.json says "<b>"`                                                            | Warning | Match the entry to `plugin.json` (authoritative at install).                                  |
| `Marketplace name "<name>" is reserved in Claude Desktop` / `... is not accepted by Claude Desktop` (marketplace or plugin) | Warning | Not `org`, `org-provisioned`, `unknown`; at most 128 chars of letters, digits, `.`, `_`, `-`. |

## Out of scope (say so, stop)

- Mods: `hooks module not loaded`, `hooks module did not load`, `claude plugin test`, `ui.render`, `$` methods, mod hooks skipped under managed settings.
- Organization policy: `Marketplace source '<source>' is blocked by enterprise policy`, `Marketplace "<name>" is not in the allowed marketplace list`, `Plugin "<name>" is blocked by your organization's policy...`, `--plugin-dir is disabled by your organization's managed settings (disableSideloadFlags)`, `Plugins from ~/.claude/skills/ are blocked...`, `Command-sourced plugins are disabled...`.
- `Marketplace '<name>' is seed-managed` (`CLAUDE_CODE_PLUGIN_SEED_DIR`).
- GitHub Enterprise Server hosts; `claudeai-*` marketplaces (`claude plugin marketplace add --claudeai <name>`); local-path marketplaces.
