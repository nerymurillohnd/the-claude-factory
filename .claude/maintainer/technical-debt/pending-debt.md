# 🧾 Pending Debt

> [!NOTE]
> Unresolved technical or maintenance conditions that cannot be fixed now. Each one has evidence, an owner and a way out. Items that are fixed, no longer apply or are kept for good move to `closed-debt.md`.

## 🎯 Entry criteria

Add an item only when all of these hold:

- A specific condition is observable or backed by traceable evidence. No speculation.
- It has a real operational, security, reliability, compatibility or maintainability impact.
- It cannot be fixed now: it waits on a decision or a spend only the user or the project's owners can make, on access or an external party, or the risk is accepted on purpose.
- A concrete next action exists, or a concrete condition that triggers reassessment.
- No other active record tracks it, such as an open issue or an ADR follow-up.

> [!WARNING]
> Do not add improvement ideas, speculation or a copy of the backlog. A problem that can be fixed now gets fixed, not logged.

## 🔄 Record maintenance

| Action | When | Rule |
| --- | --- | --- |
| ➕ Append | A new condition appears | Search both ledgers for the same condition first. |
| ✏️ Update | Evidence, impact, owner or next action changes | Revise in place. Keep confirmed facts apart from inference. |
| ✅ Close | The condition is fixed, no longer applies, or the user decides to keep it for good | Move the entry to `closed-debt.md` with the same ID and an outcome: resolved, obsolete or accepted. Never just delete it. |

> [!IMPORTANT]
> An item leaves this ledger only after its closed entry exists, with the evidence its outcome needs.

### DEBT-001 — No check keeps the READMEs consistent with the manifests and the catalog

| Field | Value |
| --- | --- |
| **Status** | 🟠 Blocked |
| **Category** | quality |
| **Owner** | unassigned |
| **Logged** | 2026-11-12 |

#### 🔎 Evidence

- **Confirmed facts:**
  - No README or catalog consistency check exists. On 2026-11-13, `scripts/generators/` and `scripts/checkers/` are empty, `scripts/validators/` holds only skill-lint (ADR_2026-11-13_own-deterministic-skill-linter, which checks skill folders, not READMEs or manifests), and `.claude/rules/` holds only `skill-lint.md`, with no `readme-consistency.md`.
  - `.claude/architecture/refactor.md` plans `scripts/validators/plugin-names-consistency.py` (line 214), `scripts/generators/catalog.mjs` (line 320), `scripts/validators/readme-catalog-consistency.py` (line 321) and `scripts/validators/plugin-versions-consistency.py` (line 339). None of them exists.
  - The root `README.md`, line 106, says `generated by scripts/generators/catalog.mjs`. That script does not exist, and `package.json` has no `generate` script. Rechecked on 2026-11-13: unchanged.
  - In the docs-maintenance skill, `references/events/plugin-change.md` and `references/events/new-version.md` end without a cross-file check. `references/events/audit.md` runs a report-only audit through `plugin-readme-writer` and `marketplace-readme-writer`, but only on request.
  - A path-scoped rule was drafted in the session on 2026-11-12, as `.claude/rules/readme-consistency.md`:
    - Paths: `README.md`, `plugins/*/README.md`, `plugins/*/CHANGELOG.md`, `plugins/*/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`.
    - Trigger: after a change set alters a fact other files repeat, launch a background docs-maintenance audit, report only.
    - Skips: no repeated fact changed, applying an audit's fixes, an audit of the same scope already run, and inside a subagent.
  - Stated by the user on 2026-11-12: if the scripts are built, the rule covers only semantic consistency, and the scripts cover the mechanical checks.
- **Inferences:**
  - Names, versions and catalog rows are mechanical and suit scripts, run through npm and CI.
  - Descriptions, prerequisites and links between plugins need judgment and suit the audit agents.
  - Plugin READMEs show their version through a dynamic badge read from `plugin.json`. Mechanical drift there is limited to the minimum Claude Code version, names and install commands, plus the version column of the root catalog.
- **Open questions:**
  - The rule, the scripts, or both, and in which order.
  - Whether the rule's paths include `plugin.json`, `marketplace.json` and the CHANGELOGs, or only the READMEs.
  - Whether to reuse the two README writers or create a dedicated auditor.
  - Whether a change to the marketplace's name, owner or categories audits all 22 plugin READMEs or asks the owner first.

#### 📈 Impact and next step

- **Impact / risk:** a name, version, description or catalog row can disagree between `plugin.json`, `marketplace.json`, a plugin README, its CHANGELOG and the root catalog. Nothing catches it before it reaches the people who install these plugins. The stale comment on line 106 of the root README points maintainers to a script that does not exist.
- **Why it is not fixed now:** it waits on the owner's choice between the rule and the scripts, and on the open questions. The owner asked on 2026-11-12 to log it rather than build it now.
- **Next action:** the owner answers the open questions. Then either write `.claude/rules/readme-consistency.md` from the 2026-11-12 draft, or build the mechanical checks as maintainer scripts behind an npm script and narrow the rule to semantic consistency.
- **Review condition:** the owner's decision, or the first README or catalog drift found in review.
- **Related records:** ADR_2026-11-12_npm-scripts-are-the-single-entry-point, ADR_2026-11-12_maintainer-tools-as-pinned-uv-tools (superseded by ADR_2026-11-12_maintainer-scripts-run-through-uv-run).
