# 🧾 Pending Debt

> [!NOTE]
> Unresolved technical or maintenance conditions that cannot be fixed now. Each one has evidence, an owner and a way out. Items that are fixed, no longer apply or are kept for good move to `closed-debt.md`.

## 🎯 Entry criteria

Add an item only when all of these hold:

- A specific condition is observable or backed by traceable evidence. No speculation.
- It has a real operational, security, reliability, compatibility or maintainability impact.
- It cannot be fixed now: it waits on a decision or a spend only the user or the project's owners can make, on access or an external party, or the risk is accepted on purpose.
- A concrete next action exists, or a concrete condition that triggers reassessment.
- No other active record tracks it, such as an open issue or an ADR follow-up.

> [!WARNING]
> Do not add improvement ideas, speculation or a copy of the backlog. A problem that can be fixed now gets fixed, not logged.

## 🔄 Record maintenance

| Action | When | Rule |
| --- | --- | --- |
| ➕ Append | A new condition appears | Search both ledgers for the same condition first. |
| ✏️ Update | Evidence, impact, owner or next action changes | Revise in place. Keep confirmed facts apart from inference. |
| ✅ Close | The condition is fixed, no longer applies, or the user decides to keep it for good | Move the entry to `closed-debt.md` with the same ID and an outcome: resolved, obsolete or accepted. Never just delete it. |

> [!IMPORTANT]
> An item leaves this ledger only after its closed entry exists, with the evidence its outcome needs.

### DEBT-001 — No check keeps the READMEs semantically consistent with the manifests and the catalog

| Field | Value |
| --- | --- |
| **Status** | 🟠 Blocked |
| **Category** | quality |
| **Owner** | unassigned |
| **Logged** | 2026-11-12 |

#### 🔎 Evidence

- **Confirmed facts:**
  - No README or catalog consistency check exists. On 2026-11-13, `scripts/generators/` and `scripts/checkers/` are empty, `scripts/validators/` holds only skill-lint (ADR_2026-11-13_own-deterministic-skill-linter, which checks skill folders, not READMEs or manifests), and `.claude/rules/` holds only `skill-lint.md`, with no `readme-consistency.md`.
  - `.claude/architecture/refactor.md` plans `scripts/validators/plugin-names-consistency.py` (line 214), `scripts/generators/catalog.mjs` (line 320), `scripts/validators/readme-catalog-consistency.py` (line 321) and `scripts/validators/plugin-versions-consistency.py` (line 339). None of them exists.
  - The root `README.md`, line 106, says `generated by scripts/generators/catalog.mjs`. That script does not exist, and `package.json` has no `generate` script. Rechecked on 2026-11-13: unchanged.
  - In the docs-maintenance skill, `references/events/plugin-change.md` and `references/events/new-version.md` ended without a cross-file check. On 2026-11-13 those events moved into the `plugin-versioning` and `plugin-releases` skills and the writer agents were retired; no cross-file check exists there either. The skill's Audit or review event checks consistency only on request.
  - A path-scoped rule was drafted in the session on 2026-11-12, as `.claude/rules/readme-consistency.md`:
    - Paths: `README.md`, `plugins/*/README.md`, `plugins/*/CHANGELOG.md`, `plugins/*/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`.
    - Trigger: after a change set alters a fact other files repeat, launch a background docs-maintenance audit, report only.
    - Skips: no repeated fact changed, applying an audit's fixes, an audit of the same scope already run, and inside a subagent.
  - Stated by the user on 2026-11-12: if the scripts are built, the rule covers only semantic consistency, and the scripts cover the mechanical checks.
  - Update, 2026-11-13: the mechanical checks are now built. `npm run check:consistency` runs `scripts/validators/plugin-consistency.py` (commit a1c4c10, ADR_2026-11-13_five-scripts-cover-release-and-consistency-checks) and is part of `npm run check`. It checks:
    - names across the folder, `plugin.json` and the marketplace entry
    - `renames`
    - changelog headings against tags
    - an empty `[Unreleased]` on `main`
    - README placeholders, length, badge and install, update and uninstall commands
    - one catalog row per plugin, at its version and category, with the section counts
    
    On the branch it exits 0. Still open:
    - the semantic part: descriptions, prerequisites and links between plugins
    - the stale `scripts/generators/catalog.mjs` comment, now on line 105 of the root `README.md`
    - the catalog generator, still Pending in `refactor.md`
- **Inferences:**
  - Names, versions and catalog rows are mechanical and suit scripts, run through npm and CI.
  - Descriptions, prerequisites and links between plugins need judgment and suit the audit agents.
  - Plugin READMEs show their version through a dynamic badge read from `plugin.json`. Mechanical drift there is limited to the minimum Claude Code version, names and install commands, plus the version column of the root catalog.
- **Open questions:**
  - The rule, the scripts, or both, and in which order.
  - Whether the rule's paths include `plugin.json`, `marketplace.json` and the CHANGELOGs, or only the READMEs.
  - Whether to reuse the two README writers or create a dedicated auditor.
  - Whether a change to the marketplace's name, owner or categories audits all 22 plugin READMEs or asks the owner first.

#### 📈 Impact and next step

- **Impact / risk:** a name, version, description or catalog row can disagree between `plugin.json`, `marketplace.json`, a plugin README, its CHANGELOG and the root catalog. Nothing catches it before it reaches the people who install these plugins. The stale comment on line 106 of the root README points maintainers to a script that does not exist.
- **Why it is not fixed now:** it waits on the owner's decision about the semantic rule and on the open questions. The owner asked on 2026-11-12 to log it rather than build it now; the mechanical scripts were built on 2026-11-13.
- **Next action:** the owner answers the open questions on the semantic rule. Then write `.claude/rules/readme-consistency.md` from the 2026-11-12 draft, narrowed to semantic consistency, since `check:consistency` covers the mechanical checks.
- **Review condition:** the owner's decision, or the first README or catalog drift found in review.
- **Related records:** ADR_2026-11-12_npm-scripts-are-the-single-entry-point, ADR_2026-11-12_maintainer-tools-as-pinned-uv-tools (superseded by ADR_2026-11-12_maintainer-scripts-run-through-uv-run), ADR_2026-11-13_five-scripts-cover-release-and-consistency-checks.

### DEBT-003 — Two CLI checks can't join npm run validate while five mods fail them

| Field | Value |
| --- | --- |
| **Status** | 🟠 Blocked |
| **Category** | quality |
| **Owner** | unassigned |
| **Logged** | 2026-11-13 |

#### 🔎 Evidence

- **Confirmed facts:**
  - `npm run validate:hooks-catch` checks `contents[].gatingHooks[].hasCatch` from `claude plugin validate --json` (commit 79af551, Claude Code 2.1.323). On 2026-11-13 it exits 1 with four hooks:
    - `plugins/project-maintainer`: `session.compact` and `tool.call{tool=Bash}`, in `./register.ts`
    - `plugins/turn-meter`: `tool.call` and `command.run{command=turn-meter}`, in `./register.tsx`
  - `npm run validate:portable` runs `claude plugin validate --profile directory --strict` on each plugin. On 2026-11-13 it fails on `file-tree-pane`, `model-trace`, `project-maintainer`, `tool-ledger` and `turn-meter`. `npm run check:install -- --from local turn-meter` shows the cause for `turn-meter`: `TS2741: Property 'isCollapsed' is missing`.
  - Both scripts stay out of `validate` and `check`. `validate:claude` and `validate:mods`, which pass, joined `validate`.
  - On 2026-11-14, with Claude Code 2.1.325, plain `claude plugin validate --strict` also exits 1 on `model-trace`, `tool-ledger` and `turn-meter`, at `main` (39b0110): `error TS2769: No overload matches this call … 'mode' does not exist in type … ToolInputOf<"WebSearch", …>` (model-trace lines 230 and 351). So `npm run validate` fails on them too.
- **Inferences:** the same mods-API type errors may mean the mods are broken for users on current Claude Code builds; whether 2.1.325 changed the WebSearch input type is not checked against the release notes.
- **Open questions:** none.

#### 📈 Impact and next step

- **Impact / risk:** nothing blocks a merge on a gating hook with no `.catch` or on a portability failure. These plugins reach users with the defects the two checks report.
- **Why it is not fixed now:** the fixes are plugin-scope work with version bumps. The owner kept them out of the scripts and CLI task on 2026-11-13.
- **Next action:** the owner schedules the fixes for the five plugins. Once `validate:hooks-catch` and `validate:portable` exit 0, chain both into `npm run validate`.
- **Review condition:** both scripts exit 0.
- **Related records:** ADR_2026-11-13_five-scripts-cover-release-and-consistency-checks.

| --- | --- |

| **Category** | quality |
| **Owner** | unassigned |
| **Logged** | 2026-11-14 |

#### 🔎 Evidence

- **Confirmed facts:**
  - `npm run lint:frontmatter` on 2026-11-14, on branch `ccr-7fcd6ef3-rku7l1` after 50662ee, reports 53 files checked and 16 findings, exit 1:
    - `plugins/github-operations`: FM-01 in the `description` of `agents/pr-lifecycle/pr-fixer.md`, `agents/pr-lifecycle/pr-tracker.md` and `agents/repo-hygiene/health-diagnostics.md`; FM-03 in the `argument-hint` of `commands/init-cleanup-and-debug.md`, `commands/init-pr-lifecycle.md` and the `auto-pr-lifecycle`, `claude-github-actions` and `cleanup-and-debug` skills.
    - `plugins/instruction-engineering`: FM-02 in the block-scalar `description` of `agents/reviewer.md`.
    - `plugins/plugin-test-bench`: FM-03 in the `argument-hint` of the `review-evals` and `test-install` skills.
    - `plugins/prompt-writer`: FM-02 in the hook `prompt` of the `prompt-writer` skill.
    - `plugins/svelte-development`: FM-03 in `metadata.upstream` and `metadata.base` of the `svelte-best-practices` and `svelte-docs-and-autofixer` skills.

- **Inferences:** none.
- **Open questions:** github-operations 0.8.1 must wait until 0.8.0 has its tag, or `release.yml` never tags 0.8.0.

#### 📈 Impact and next step

- **Impact / risk:** the 16 values break the owner's frontmatter rule, and the three FM-01 agents fail strict YAML parsers other than Claude Code's. Until they are fixed, `lint:frontmatter` stays out of `npm run lint` and `npm run check`, so nothing stops a new violation.
- **Why it is not fixed now:** the fixes are plugin-scope changes with version bumps in five plugins, and the github-operations one waits on the 0.8.0 release. The owner schedules plugin fixes.
- **Next action:** the owner schedules the fixes; each plugin rewords its values without colons, quotes or leading brackets in its own pull request with a patch bump. Then chain `npm run lint:frontmatter` into `npm run lint`.
- **Review condition:** `npm run lint:frontmatter` exits 0.
- **Related records:** ADR_2026-11-14_frontmatter-lint-forbids-colons-and-quotes-in-values.
