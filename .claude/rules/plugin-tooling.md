# Plugin Tooling Rules

## Portability and platforms
- Keep plugins self-contained and prioritize Linux and macOS with POSIX-compatible interfaces.
- Support Windows only through Git Bash and only when the plugin's README declares Windows support.

## Plugin Python
- Run plugin Python with the user's `python3` from `PATH`; never rely on maintainer uv, PEP 723 execution, or the maintainer's Python version.
- Write plugin Python for any `python3` a user may have; declare a minimum in the README only when a feature requires it.
- Type-check plugin Python with Basedpyright in its default `recommended` mode.

## Documentation
- Document every required tool, version constraint, binary, and software dependency in each plugin's `README.md`, including feature-specific prerequisites.

## Dependencies
- A plugin that needs Node packages ships its own `package.json` and npm or Bun lockfile in `plugins/<name>/`, which Claude Code installs into that plugin's cache; it never relies on the root `package.json`.

## Validation and testing
- Validate every plugin with `claude plugin validate --strict`.
- Test mod plugins with `claude plugin test` and type-check them with `tsc` against declarations generated by the engine.
- Test plugin scripts with their own tests under `scripts/tests/<plugin>/`; keep maintainer-only test dependencies out of plugin runtimes.
- Add evals only when explicitly requested.

## Executable scripts
- Give every executable plugin script, especially Claude Code hooks, its interpreter's shebang: `#!/usr/bin/env python3`, `#!/usr/bin/env bash`, or `#!/usr/bin/env node`.
- Mark executable plugin scripts with `chmod +x` and preserve their executable bits in Git.
