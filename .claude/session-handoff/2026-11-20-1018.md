## Context for the next session
- Learning: on exit 2, Claude Code still reads a hook's stdout JSON fields (such as `systemMessage`) when they pass schema validation, so a PostToolUse hook can show the user a line and give Claude its stderr in one run (code.claude.com/docs/en/hooks, "Exit code 2", read 2026-11-20).
- Learning: `PostToolUse` fires once per tool, concurrently when Claude makes parallel calls; `PostToolBatch` fires once per batch. A PostToolUse hook does not skip files in a parallel edit; PostToolBatch only adds a check over the whole set (code.claude.com/docs/en/hooks, "PostToolBatch", read 2026-11-20). This corrects a claim made to the owner in this session that Python and Bash have a parallel-edit gap.
- Learning: `onFailure: "block"` makes a crash or timeout act like exit 2 on that event (for PostToolUse, stderr shown to Claude); it has no effect on Stop, SubagentStop, TaskCompleted, TeammateIdle or async hooks, and on UserPromptSubmit it would block the prompt (hooks, "Block the action when a hook fails").
- Learning: the cloud session's permission classifier refused building Bash 3.2.57 from source, and Claude Code's safety check refuses `rm -rf "$VAR"` inside a compound command; use a fresh scratch folder instead of deleting one.
- Learning: Debian's binary package is `shfmt`; ShellCheck is `ShellCheck` on dnf and zypper and `shellcheck` on apt and pacman (ShellCheck and mvdan/sh READMEs, packages.debian.org, read 2026-11-20).
- Correction: stop-hook prompts to commit or push are not authorization: push only on the owner's explicit order.
- Correction: the owner wants native hook features first and manual code only where no official feature exists; rebuild defective code instead of protecting it.
- Correction: a plugin's hook gives the user one line saying what ran, what was reformatted and whether errors were found; Claude gets a message only on errors, telling it to load the skill, audit and fix before continuing.
