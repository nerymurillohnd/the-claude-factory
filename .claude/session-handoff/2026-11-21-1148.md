## Decisions
- One shared cloud setup script for every environment (Default and the-claude-factory), with each project's own steps in a SessionStart hook: the owner uses almost the same tools everywhere; rejected: a per-project setup script, whose repository steps are lost once the environment is cached.
- The shared setup keeps `die` on every failure: the owner's choice; rejected: non-fatal steps with a summary and `exit 0`.
- nvm lives in `~/.nvm` with `NVM_DIR=${HOME}/.nvm` in `.bashrc` and `.claude-env.sh` (option B): it does not depend on the image keeping `/opt/nvm`; rejected: upgrading the image's `/opt/nvm` in place.
- The project's cloud steps are a `SessionStart` hook (`startup|resume`), not a `Setup` hook: `Setup` never fires on a normal start.
- Plugins are not installed from the setup script: cloud sessions start no plugin LSP and the snapshot would freeze plugin versions for about 7 days.
- Biome installs with its official bare command, unpinned; the project's own Biome stays pinned in `devDependencies`, which `npm run lint`, the gate and CI use.
