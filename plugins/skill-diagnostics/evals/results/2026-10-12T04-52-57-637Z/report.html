The skill is small and mostly clean. I found no blocking problems, only a few minor gaps.

**What it does:** `skills/word-count/SKILL.md` counts the words in one text file and replies with `<path>: <n> words`.

**Strengths**
- The frontmatter is valid. The `name` matches the directory, and the description says both what the skill does and when to use it.
- The scope is narrow: one file, one output line.
- It says what to do when there's no path: ask for one.
- It has no scripts, no network access and no unusual instructions, so there's nothing to review for security.

**Minor issues**
1. **Large files:** Step 1 says "Read the whole file", but the Read tool returns at most 2000 lines by default. For a long file the count would be silently low. Suggested wording: "Read the whole file, paging with offset/limit if it is long." Better still, run `wc -w <path>`, which is exact and cheap.
2. **Counting is by hand:** Step 2 asks the model to count words itself. That is error-prone for anything beyond a short file, which is another reason to use `wc -w`.
3. **Word definition:** The definition mentions only spaces and line breaks. Tabs aren't covered, and neither are hyphenated words or markup. Saying "whitespace-separated, as `wc -w` counts" would settle it.
4. **Failure cases:** Nothing covers a missing file, a directory, or a binary file. A short line such as "If the file can't be read or isn't text, say so instead of giving a count" would handle all three.
5. **Multiple files:** The skill takes one file only. The description says so, but a request naming several files would have no defined behavior.

**Suggested rewrite of steps 1–2:**
```
1. Run `wc -w <path>`. If the file is missing, a directory, or binary, say so and stop.
2. Take the number from the output.
```

I haven't changed anything. I can apply the rewrite if you want.

1. **Conflicting save location.** `SKILL.md` step 4 says to save to `drafts/reminder.md`. `references/delivery.md` says every reminder goes in `outbox/<invoice_id>.md` so the mail job can send it. - The `description` field is fine for triggering.
- The skill has no tone or length guidance. The template is short enough that this may be deliberate.

To fix it, make step 4 point to `outbox/<invoice_id>.md`. Add a line saying how to get `grace_date`, for example "today + N days" or "ask the user if not given".
